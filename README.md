# SmartTutor

A personal, self-paced learning platform where users create their own study content and the system helps them retain it. Think Duolingo, but the user owns and defines the curriculum — from Spanish vocabulary to Roman history to anatomy.

There is no fixed curriculum. The user defines what they want to learn, builds tests with different question types, takes exams, and reviews weak areas using spaced repetition.

## Features

### Content Creation

Users build **Tests** — named collections of questions that can mix different types:

- **Simple (free-text):** User types an answer. Multiple valid answers supported (synonyms). Typo tolerance via Levenshtein distance.
- **Multiple Choice:** 2–6 options, one or more correct. Exact-match grading.
- **Long Text:** Paragraph-style answers (short / medium / long tiers). Graded by AI against a rubric of weighted criteria.
- **Question Groups:** Organizational containers for batch question patterns (e.g. a vocabulary table with 20 translation pairs under a shared title).

### Exam Engine

Select a test, answer every question, submit, and get a scored result. Supports weighted scoring — each question and group can carry different point values. PARTIAL credit (50%) for close-but-not-exact Simple answers. Results are persisted with per-question breakdowns.

### Spaced Repetition (SRS)

An SM-2-based review system surfaces questions the user keeps getting wrong. Questions are scheduled based on performance: correct answers increase the review interval, wrong answers reset it. The review flow is separate from exams — exams assess, reviews teach.

### Results History

Every exam creates a detailed result record: overall score, points breakdown, per-question status (correct / partial / wrong / pending), and timestamps. Users can browse past results to track progress over time.

### Study Notes

Users create or import Markdown study notes for reference material. Notes can also be generated by AI given a topic and optional guidance. A split-panel editor shows raw Markdown alongside a live preview.

### AI Features

AI powers four capabilities: Long Text answer grading, challenge re-evaluation of disputed grades, study note generation, and test generation from notes. Two providers are supported (Anthropic Claude Haiku 4.5 and OpenAI GPT-4o-mini), switchable via environment variable. See [AI Features](docs/ai-features.md) for architecture details.

### AI Test Generation

Users can generate tests automatically from study notes. The AI creates Simple and Multiple Choice questions matching the user's preferences (count, difficulty, types). A preview step lets users accept, reject, or refine questions before saving.

| Frontend | Next.js 16 (App Router), TypeScript, Tailwind CSS, TanStack Query, shadcn/ui |

| Infrastructure | Docker Compose (local dev), Render (backend), Vercel (frontend) |

## Architecture

### Backend — Three-Layer Pattern

```
Route → Service → CRUD → Model
```

- **Routes** handle HTTP concerns only (status codes, request/response).
- **Services** own business logic, validation, and orchestration.
- **CRUD** functions are atomic database operations with no business logic.

### Frontend — Feature-Driven

```
src/
├── components/ui/       # Low-level UI primitives (shadcn)
├── features/            # Feature modules (auth, tests, history, review, notes)
│   └── {feature}/
│       ├── components/  # Feature-specific components
│       ├── store/       # Zustand stores (if needed)
│       └── hooks/       # Custom hooks
├── client/              # Auto-generated API client (never edit)
└── lib/                 # Shared utilities, API config, routes
```

### Data Model

```
User
 ├── Test
 │    ├── Question (standalone — Simple, MC, or Long Text)
 │    └── QuestionGroup
 │         └── Question (grouped — Simple only)
 └── Note (standalone Markdown study material)
```

Questions store type-specific data (answers, options, rubrics) in a JSONB `content` column. Validation happens at the Pydantic layer, keeping the database schema simple and migration-free when adding new question type features.

## Getting Started

### Prerequisites

- Docker & Docker Compose
- Node.js 18+
- A PostgreSQL database (or use Neon.tech)

### Setup

```bash
# Clone the repo
git clone https://github.com/PepeM112/smart-tutor.git
cd smart-tutor

# Create backend .env
cp backend/.env.example backend/.env
# Fill in DATABASE_URL, JWT_SECRET, and at least one AI key (ANTHROPIC_API_KEY or OPENAI_API_KEY)

# Start backend + database
make build

# Install frontend dependencies and start dev server
cd frontend
npm install
npm run dev
```

### Useful Commands

```bash
make up                  # Start all services
make build               # Build and start in detached mode
make test                # Run backend tests
make lint                # Check linting (backend + frontend)
make fix                 # Auto-fix linting issues
make migrate-upgrade     # Apply pending database migrations
make frontend-gen        # Regenerate TypeScript API client from OpenAPI schema
make seed                # Seed database with sample data
```
